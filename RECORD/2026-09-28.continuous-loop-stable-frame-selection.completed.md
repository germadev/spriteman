# Continuous Loop and Stable Frame Selection

## 1. Goal / Context
Remove the empty frame at the playback loop boundary and keep the selected timeline frame stable during playback.

## 2. Tasks & Changes
- Added a shared floor-based discrete frame index helper with modulo normalization.
- Replaced rounded playback sampling in the canvas, onion skin, editing operations, stepping, and pivot/group lookups.
- Preserved continuous fractional frame time for WASM transform interpolation while discrete pixel cels use valid integer indices.
- Added a separate `selectedFrame` input to the frame strip so playback no longer moves the active timeline cell.
- Updated explicit navigation actions to change selection: frame click, previous/next, add, reorder, duplicate, delete, and animation changes.
- Updated play/pause so playback starts from the selected frame and pausing restores the selected frame on the canvas.
- Preserved the previous behavior where manual previous/next navigation pauses playback.

## 3. Verification
- Added boundary tests proving frame 23.99 maps to cel 23, frame 24 wraps to cel 0, and negative time normalizes correctly.
- `npm test`: 69 web tests and 13 Rust tests passed.
- `npm run build:web`: production bundle built successfully.
- Browser verification at `http://127.0.0.1:3012/#tabs=sample_walk` confirmed:
  - A selected timeline frame stayed active throughout playback.
  - Pausing restored the same selected frame and indicator.
  - The engine produced 37 distinct interpolated matrices during a sampled cycle while only one timeline cell remained active.
