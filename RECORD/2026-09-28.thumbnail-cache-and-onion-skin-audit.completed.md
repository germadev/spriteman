# Thumbnail Cache and Onion Skin Audit

## 1. Goal / Context
Audit and repair intermittent timeline thumbnail rendering and onion-skin toggling failures.

## 2. Tasks & Changes
- Added the structural frame epoch to thumbnail cache keys so project replacement, insertion, deletion, and reordering cannot reuse stale image data from an earlier frame layout.
- Invalidated the structural frame epoch whenever a project document is loaded.
- Synchronized `FrameStrip` with the current `onionSkinEnabled` animation state so repeated clicks toggle both directions.
- Aligned canvas onion-skin selection with the animation service by wrapping frame zero to the final frame.
- Added a regression test proving that document replacement advances the thumbnail cache epoch.
- Audited the bundled `sample_walk` example and found that it references a missing `public/assets/hero.png`; its original frames contain no editable pixel maps, so their thumbnails remain blank independently of cache invalidation.

## 3. Verification
- `npx vitest run src/__tests__/project.service.test.ts`: 12 tests passed.
- `npm run typecheck`: passed.
- `npm test`: 64 web tests and 13 Rust tests passed.
- `npm run build:web`: production bundle built successfully.
- Browser verification at `http://127.0.0.1:3000/#tabs=sample_walk`:
  - Painting a pixel changed the first thumbnail from zero to one non-white pixel.
  - Onion skin toggled active, inactive, and active across two clicks.
  - At frame zero, disabling onion skin changed the canvas and re-enabling it restored the exact previous canvas image, using the final frame as the previous frame.

## 4. Status
Completed. The editable pixel-frame thumbnail and onion-skin defects are fixed and verified. The missing spritesheet asset/rendering path in the legacy sample remains a separate content/rendering issue.
